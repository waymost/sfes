# 0013. Test-cartridge toolchain

- **Status:** accepted
- **Date:** 2026-11-18
- **Confidence:** high

## Context

EMU-11 asks for small test cartridges written by the project in 65816 assembly, permissively licensed and committed, where documents are silent or a behaviour needs a whole machine to show. From M2 every machine and PPU feature issue adds one. That needs an assembler and a linker, a fixed layout, a rule for how a cartridge cites what it tests, and a way to keep the committed ROM in step with its source.

## Sources

- FSD EMU-11 (own cartridges, expected values cited), PROV-03 (source tags), PROV-08 and PROV-09 (asset licenses and the manifest).
- `fullsnes#snescartridgeromheader`: the header at `$FFC0–$FFDF` and the exception vectors at `$FFE0–$FFFF`, found at ROM offset `$7FC0` for LoROM and `$FFC0` for HiROM; the ROM size byte is `(1 SHL n)` KiB; the checksum is every ROM byte added together with `$FFDC–$FFDF` taken as `FF FF 00 00`, and the complement is the checksum XOR `$FFFF`.
- `fullsnes#snescartlorommappingromdividedinto32kbanksaround1500games` and `fullsnes#snescarthirommappingromdividedinto64kbanksaround500games`: where LoROM and HiROM banks appear in the CPU's address space.
- `wdc-w65c816s#table-5-2` and `wdc-w65c816s#table-5-3`: the emulation- and native-mode vector locations.
- ADR 0003: tooling lives in `xtask`, outside the crate graph.

## Decision

- **Toolchain:** ca65 and ld65 from cc65, release 2.19 (git tag `V2.19`), zlib-licensed. That release's tools report themselves as `V2.18`, and `cargo xtask carts` refuses to run with any other version. CI builds the tag from source; locally the Homebrew `cc65` formula installs the same release.
- **Built ROMs are committed.** Tests, the player and the golden runner need no assembler, so macOS and Windows contributors and CI jobs never install cc65. A review shows the assembly source diff; one Linux CI job rebuilds every cartridge and fails if a committed ROM differs in any byte.
- **Layout:**
  - `tests/carts/<name>/<name>.s` is the entry source; other `.s` files in the directory are assembled and linked with it. `tests/carts/<name>/cart.toml` names the board (`board = "lorom"` or `"hirom"`).
  - `tests/carts/common/` holds `header.inc` (the `cart_header` and `cart_vectors` macros), `lorom.cfg` (32 KiB, one bank at `$8000–$FFFF`) and `hirom.cfg` (64 KiB, the low half at `$C0:0000`, the high half at `$8000`, where the CPU starts in bank `$00`).
  - The built ROM is `tests/assets/carts/<name>.sfc`, recorded in `tests/assets/MANIFEST.toml` with `license = "own"` and its SHA-256. `tests/carts/` holds sources only.
- **Commands:** `cargo xtask carts build` assembles and links every cartridge, then writes the ROM size byte (`$FFD7`) and the checksum and complement (`$FFDC–$FFDF`) as fullsnes describes, so the header is valid without hand-computed values. `cargo xtask carts check` does the same into `target/carts/` and compares the result with the committed ROM.
- **Citations:** every source file starts with a `; @source:` tag, and every `.proc` and `.macro` carries one in the comment lines directly above it, naming the document section whose behaviour it exercises. `cargo xtask provenance lint` enforces both and checks the ids. An expected value the cartridge compares against carries its own citation in the comment beside it. A value checked outside the cartridge (by a Rust test or a golden hash) is cited by that test. Per EMU-11 an expected value comes from a document, a hardware measurement or oracle output; oracle output needs an ADR naming the oracle and its version (M2 tracking issue, rule 5). Conventions a cartridge invents, such as a marker value it writes, are described in its source and cite this ADR.
- **License:** cartridge sources and built ROMs are the project's own work under `MIT OR Apache-2.0`, like the rest of the repository.

## Consequences

- Adding a cartridge is a directory, a `cart.toml`, a manifest entry and `cargo xtask carts build`. `cargo xtask provenance assets` reports a cartridge without a manifest entry, and a file in `tests/carts/` that is not a source.
- A cc65 release that changes the generated bytes would fail `carts check`. Moving to it is a change to this ADR and a rebuild of every ROM in one PR.
- Larger cartridges (more LoROM banks, ExHiROM) add linker configs and board names here when an issue needs them.
- `.gitignore` ignores `*.sfc` everywhere except `tests/assets/carts/`, so a commercial ROM still cannot be added by accident.
