# 0026. HDMA

- **Status:** accepted
- **Date:** 2026-11-20
- **Confidence:** high for the registers, the table format, the line counter and the per-line steps; medium for when the steps run and what each costs; low for the overhead's exact length, where it falls, the last-channel oddity at frame start, a channel enabled mid-frame and the end of a pre-empted DMA

## Context

HDMA uses the eight DMA channels (ADR 0025) to move one unit of up to four bytes per channel per line, from a table in A-bus memory to B-bus registers. The hardware does it in two places in a frame: once at the start of the frame, to set up each enabled channel from its table, and once per visible line, at the start of horizontal blank. The CPU is paused while it runs, and HDMA pre-empts a general DMA transfer.

The technical design (section 4) lists "HDMA setup at frame start and the per-line HDMA transfer" among the deadlines, and catch-up rule 4 has general DMA check the HDMA deadline between bytes. ADR 0025, point 9 leaves the HDMA deadline to this work.

The sources agree on the registers, the table format, the line counter and the order of the per-line steps. They give the costs as approximate counts and say the pause's timing is "presumably" that of DMA. They leave open:
- where the overhead falls and its exact length;
- whether the last-channel oddity applies at frame start;
- what a channel enabled mid-frame does on its first line;
- what "involve the current DMA channel" means and what the pre-empted channel is left with.

## Sources

- `anomie-regs#420c`:
  - Each set bit enables a channel, "executed in order from 0 to 7 (?)".
  - HDMA during a DMA pauses the DMA. If the HDMA "happens to involve the current DMA channel, the DMA will be immediately terminated and the HDMA will progress using the then-current values of the registers". Other DMA channels are unaffected. `anomie-regs#420b` says the same.
  - A channel enabled mid-frame begins at the next HDMA point, but the registers are set up only before the HDMA point of line 0, so they must be set by hand. A channel that has terminated for the frame cannot be restarted this way.
  - Writing 0 to a bit pauses the channel. Writing 1 continues it.
  - `$00` at power-on and reset.
- `anomie-regs#43x0`:
  - Bit 7, the direction, does affect HDMA. Indirect mode reads the table as normal and writes from the B bus to the indirect address. Direct mode "will read counts from the table and try to write the data values into the table".
  - Bit 6 selects indirect addressing. Bits 4–3 do not affect HDMA.
  - The modes are those of DMA.
- `anomie-regs#43x2`: `$43x2–$43x4` hold the table's start. Only a write to `$43x4` mid-frame is thought to affect the transfer, and HDMA does not change these registers.
- `anomie-regs#43x5`:
  - For HDMA, `$43x7` is the bank of the indirect address. The indirect address is copied into `$43x5/6` and incremented. Direct HDMA neither uses nor changes them.
  - Writes to `$43x5–$43x7` during indirect HDMA take effect for the next transfer.
- `anomie-regs#43x8`: at the start of the frame `$43x2/3` are copied into `$43x8/9` for every active channel. `$43x8/9` are then updated as the table is read. A write mid-frame changes the table address for the next line.
- `anomie-regs#43xa`:
  - Bit 7 is repeat. Bits 6–0 are the line count, decremented each line. When it reaches 0, a byte is read from the table into `$43xA`, with the indirect address too if applicable.
  - "The register is decremeted before being checked for r status or c==0." `$80` is 128 lines without repeat, and `$00`, when it does not mean "terminate", is 128 lines with repeat.
  - It is set at the end of vertical blank for every active channel. A write mid-frame takes effect the next line.
  - All of `$43x7–$43xA` are `$FF` at power-on and unchanged on reset.
- `anomie-regs#dma-and-hdma`: HDMA takes priority over DMA, "pausing all DMA and terminating a conflicting DMA immediately". Lower-numbered channels take priority.
- `anomie-regs#dma-and-hdma/hdma`:
  - One pass through the transfer mode per line: mode 0 writes 1 byte per line, mode 2 writes 2.
  - Each line on which HDMA is active (at least one channel neither paused nor terminated) costs "~18 master cycles overhead". Each active channel costs another 8 "whether or not a transfer actually occurs", during which `$43xA` is "presumably" loaded. A new indirect address costs 16. Each byte costs 8. The maximum is 466 cycles per line.
  - At V=0, H≈6, for every active channel: copy AAddress into Address, load `$43xA` from the table ("$00 will terminate this channel immediately", it believes), load the indirect address if needed, and set DoTransfer. The overhead is ~18 cycles, plus 8 per direct channel and 24 per indirect channel.
  - A channel started mid-frame must have `$43x8–$43xA` (and `$43x5/6` for indirect) set by hand. "There is no way to perform step 4, so no transfer will be done the first transfer period." It adds: "XXX: Or does it automatically do Step 4 when you enable the channel?"
  - For each line from V=0 to `$E0` (`$EF` with overscan), at about H=`$116`:
    1. If DoTransfer is set, read one byte per byte of the mode from Address or Indirect Address, incrementing it, and write each to Port plus the mode's offset. The notes on WRAM through both buses apply.
    2. Decrement `$43xA` and set DoTransfer to Repeat.
    3. If the line count is zero, read the next table byte into `$43xA`. In indirect mode, read two bytes into Indirect Address. "One oddity: if $43xA is 0 and this is the last active HDMA channel for this scanline, only load one byte for Address, and use the $00 for the low byte." Address then ends one less than expected and one less CPU cycle is used.
    4. If `$43xA` is zero, terminate the channel for this frame. Its `$420C` bit is not cleared. Otherwise set DoTransfer.
  - HDMA does not occur during vertical blank. The table format follows from the steps.
- `anomie-timing#s-cpu/hdma`:
  - The CPU is halted during HDMA, and HDMA takes priority over DMA.
  - Setup is "at about V=0 H=6": ~18 cycles, plus 8 per direct channel and 24 per indirect channel. "Presumably, the exact timing for the HDMA pause is the same as that for DMA."
  - Channels may be deactivated by a `$00` line count, "possibly" by writing `$00` to `$43xA`, or by `$420C`. All are deactivated at the start of vertical blank.
  - The transfer "begins at dot 278 of the scanline (or just after, the current CPU cycle is completed before pausing)", on every visible line, 0–224 or 0–239 by `$2133` bit 3. The costs are as anomie-regs gives them.
- `anomie-timing#s-cpu/dma`: the DMA pause aligns to 8 cycles since reset and ends on a whole CPU Clock since it began (ADR 0025, points 3 and 4).
- `anomie-regs#2133`: turning overscan off at the start of line X (`$E1`–`$F0`) makes the last HDMA happen on line X−1. Turning it on at line `$E1` delays NMI to `$E2` "although the last HDMA will still occur on line E0".
- `fullsnes#snesdmaandhdmastartenableregisters`: channel 0 first, HDMA has priority over DMA, and "HDMA is running even during Forced Blank".
- `fullsnes#snesdmaandhdmachannel07registers`:
  - One unit, up to 4 bytes, per line.
  - For HDMA, `$43x2–$43x4` are the table's start and bank. `$43x8/9` are the current table address in that bank, "incrementing". `$43x5/6` are the current indirect address, loaded from the table, and `$43x7` its bank, set by software.
  - `$43xA`: `$00` terminates the channel until the next frame. `$01–$80` transfer one unit, then pause for X−1 lines. `$81–$FF` transfer X−`$80` units on X−`$80` lines.
  - Counts and pointers are always read. Data is read or written by the direction. The step is "always INCREMENTING", for the table and for indirect data.
- `fullsnes#snesdmaandhdmanotes`: HDMA should be enabled during vertical blank, so that the registers are reloaded at its end. Started mid-frame with `$420C` previously zero, the channel "will behave as expected". Started while another channel was already active, it "does apparently start with do_transfer=1 (for whatever reason)". This case "may need more research".
- `fullsnes#snestiminghvevents`: "H=6, V=0 reload HDMA registers" and "H=278, V=0..224 perform HDMA transfers", before each line and after the last.

No source gives:
- the exact overhead, or where it falls among the channels' work;
- whether the last-channel oddity applies at frame start;
- what DoTransfer a channel enabled mid-frame starts with, beyond the two conflicting observations above;
- which channels count as "involved" for ending a DMA.

## Decision

1. **The registers.**
   - `$420C` HDMAEN is write-only: a read is open bus. It holds the enabled channels. It is 0 at power-on and reset.
   - `$43x7–$43xA` are the channel registers of ADR 0025, point 1. HDMA reads and changes `$43x5/6` (indirect mode), `$43x8/9` and `$43xA`, and never `$43x2–$43x4` or `$43x7`.
   - Each channel also has two internal flags: DoTransfer, and terminated-for-this-frame. Both are clear at power-on and reset.
2. **When the steps fall due.**
   - Setup at H=6 of line 0, 24 master cycles after the line starts.
   - A line's transfer at H=278, 1112 master cycles after the line starts, on every line that starts before vertical blank begins: lines 0–224, or 0–239 with overscan, which `$2133` decides as for vertical blank (ADR 0020, point 6). So turning overscan off at line X makes X−1 the last. The `$E1` turn-on case of `anomie-regs#2133` is not modelled.
   - Both are deadlines, serviced in table order after the others due at the same time (ADR 0020, point 9).
3. **When the pause begins.**
   - A step that falls due while the CPU runs waits for the CPU cycle it fell in to complete, as anomie-timing says. Its pause begins at the start of the next CPU access. That access's length is the CPU Clock, and the pause is timed as DMA's (ADR 0025, points 3 and 4): wait to a multiple of 8 cycles since reset, do the work, then wait to a whole CPU Clock since the pause began.
   - If a general DMA is also due at that access, both run in one pause: HDMA first, then the DMA's overhead and channels.
   - A step that falls due during a DMA pause runs at the end of the slot, overhead or wait it fell in, inside that pause, with no wait of its own. The DMA's closing wait covers both.
   - A step with no channel to work on takes no time and does not pause the CPU.
4. **What a step costs.**
   - 18 master cycles of overhead if any channel is worked on: anomie's "~18", taken as exact and placed first.
   - Then, for each channel worked on, from 0 to 7: 8 cycles, plus 8 per byte moved and 16 per indirect address loaded (8 in the last-channel oddity).
   - This gives setup's 18 + 8 per direct channel + 24 per indirect channel, and the line maximum of 18 + 8 × (8 + 16 + 32) = 466.
   - Each byte, table byte or data, moves at the start of its 8-cycle slot, as in DMA (ADR 0025, point 5). The table bytes of a reload are read at the end of the channel's work for the line.
5. **Setup** works on every channel enabled in `$420C`, from 0 to 7. First every channel's terminated flag clears. Then, for each enabled channel:
   - copy `$43x2/3` into `$43x8/9`;
   - reload, as in point 6, without the last-channel oddity, which the sources give only for the per-line step;
   - so DoTransfer is set, and a `$00` line count terminates the channel. Its indirect address is still read first, as in the per-line step.

   A channel not enabled at setup keeps its DoTransfer.
6. **A line's transfer** works on every channel that is enabled and not terminated, from 0 to 7. For each one:
   - If DoTransfer is set, move one unit of the mode's length. Each byte's A-bus address is `$43x8/9` in bank `$43x4` (direct) or `$43x5/6` in bank `$43x7` (indirect), incremented after each byte and wrapping at 16 bits with the bank kept. The B-bus address is `$21pp` plus the mode's offset, as for DMA. Bit 7 sets the direction, so direct mode from the B bus writes into the table.
   - Decrement all of `$43xA`, wrapping at 8 bits, and set DoTransfer to its bit 7.
   - If bits 6–0 are now 0, reload:
     - Read the next table byte into `$43xA` and increment `$43x8/9`.
     - In indirect mode, read two bytes into `$43x5` and `$43x6` and increment `$43x8/9` twice. The oddity: if the byte read is `$00` and this is the highest-numbered channel worked on in this line, read only one byte, into `$43x6`, set `$43x5` to `$00`, and charge 8 cycles instead of 16.
     - If `$43xA` is `$00`, the channel is terminated for the frame, leaving its `$420C` bit set. Otherwise set DoTransfer.
7. **Enabling, pausing and writing mid-frame.**
   - A channel enabled after setup starts at the next line's transfer from its registers as they stand, with its DoTransfer as last left. A channel that has not run since power-on or reset, or that ran out of a table, has DoTransfer clear and moves nothing on its first line, as anomie-regs says. fullsnes's second case, a channel that starts with DoTransfer set, is not modelled.
   - A terminated channel stays terminated until the next setup.
   - A clear `$420C` bit pauses its channel: the channel is skipped at no cost, and its state is kept.
   - CPU writes to `$43x0–$43xA` take effect at the next step that reads them, since every step reads the registers as they stand. A `$00` written to `$43xA` does not terminate the channel by itself. It is 128 lines with repeat after the next decrement, as anomie-regs says.
8. **The A and B buses** are as for DMA (ADR 0025, points 6 to 8): table bytes and data reach what a DMA reaches, WRAM through both buses fails the B side, and every byte read or moved, table bytes included, is placed on the data bus.
9. **Pre-empting a DMA.** A DMA channel that is moving bytes when a step works on the same channel ends there. Its `$43x2/3` and count are left as the DMA left them, then changed only by what HDMA itself changes. Channels later in the `$420B` value run as usual. "Involve" is taken to mean a channel the step works on, by points 5 and 6. A channel that is only enabled but already terminated or not enabled does not end the DMA.
10. **Events.** Each data byte reports one `on_dma` event with `hdma: true`, in the form of ADR 0025, point 11. Table bytes are not reported.

## Consequences

- `bus/dma.rs` becomes `bus/dma/mod.rs`, with `bus/dma/hdma.rs` beside it for the steps. The DMA pause becomes a pause for DMA, HDMA or both.
- The timing module gains an HDMA deadline, set at each line start (setup on line 0, then the transfer) and an `Event::Hdma` the bus answers by marking the step due.
- The DoTransfer and terminated flags join the bus state, and the save-state envelope (M4) must carry them.
- The PPU issues (M2, PPU work) take HDMA's register writes through the B bus. HDMA at H=278 of line L changes the registers line L+1 renders, which matches catch-up rule 2.
- Unit tests cover:
  - the deadlines' times;
  - `$420C`;
  - setup;
  - direct, indirect and repeat tables;
  - the line counter's `$80` and `$00` cases;
  - termination and the oddity;
  - costs;
  - pausing;
  - mid-frame enable;
  - the end of vertical blank;
  - pre-emption of a DMA;
  - `on_dma`.
- The `hdma` test cartridge runs direct and indirect tables into the WRAM port, and `src/carts.rs` checks the WRAM it leaves.
- We revisit:
  - point 4 if a test ROM measures the HDMA pause;
  - point 7 if fullsnes's second case is confirmed;
  - point 2 if the `$E1` overscan case matters to a game;
  - point 9 if a test ROM shows what a pre-empted channel is left with.
